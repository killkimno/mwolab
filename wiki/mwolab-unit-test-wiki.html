MwoLab 유닛 테스트 위키

기준일 2026-08-09 · MwoLab 구현 위키의 테스트 전용 문서

tests/mechlab-formulas.test.js와 tests/quirk-calculations.test.js가 검증하는 멕랩 계산식, 실행법과 유지 규칙을 정리한다.

브라우저 화면이나 로컬 미리보기 서버를 사용하지 않고 Node 내장 테스트 러너에서 public/app.js와 public/quirk-calculations.js의 실제 계산 함수를 직접 호출한다. 화면용 복제 공식은 만들지 않는다.

목적과 적용 시점

  • 공식 수정 전 기존 기대값을 확인하고 수정 후 관련 없는 계산이 바뀌지 않았는지 검사한다.
  • 장갑, 구조, 톤수, 슬롯, 무기, 탄약, 쿼크, 기동, 센서, 점프젯, 발열, 시뮬레이션 결과에 영향을 주는 작업에서 전체 테스트를 실행한다.
  • 게임 데이터 추출 규칙이나 원본 필드 해석이 계산 결과에 영향을 주는 경우에도 실행한다.
  • 현재는 로컬 수동 검증용이며 커밋·푸시 때 자동 실행되는 CI에는 연결되어 있지 않다.

테스트 구조

Node test runner → quirk-calculations.js 직접 테스트 + VM 샌드박스에서 app.js 통합 테스트 → 예상값 비교
  • public/quirk-calculations.js는 브라우저 전역과 Node module.exports 양쪽에서 같은 공용 API를 제공한다.
  • 테스트 모드에서는 앱 초기화와 JSON 로딩을 생략하고 공식 테스트 API만 노출한다.
  • VM은 DOM, 저장소, 위치 정보의 최소 스텁만 제공하며 네트워크 요청을 허용하지 않는다.
  • 테스트 API는 테스트 전용 진입점이며 앱 화면이나 배포 기능의 공개 API가 아니다.
  • calculateBuild() 집계 테스트로 개별 공식과 최종 피팅 요약이 같은 기준을 쓰는지 확인한다.

개별 테스트 항목

71개 실제 검증 사례와 일곱 개 상위 그룹 노드로 구성되어 현재 총 78개 테스트 노드가 통과한다.

탐색·공유

  1. 쿼크 보유·수치 필터 — 빈 입력의 이름 보유 판정, 퍼센트·일반 수치 하한과 모두·하나라도 포함 방식을 확인한다.
  2. 공유 URL 코드 보존 — 특수문자를 포함한 MWO 코드를 쿼리 문자열에서 정확히 복원한다.
  3. 피팅 탭 독립성 — 중복 멕 탭의 빌드 객체를 따로 유지하고 활성 탭만 교체하는지 확인한다.
  4. 빈 탭 슬롯 포커스 — +로 선택한 빈 슬롯이 주 화면 복귀 상태 전환 뒤에도 유지되고, IMPORT를 포함한 피팅 확정이 사용하는 공용 할당 경로의 교체 요청을 기존 탭 교체 없이 새 탭 추가로 바꾸는지 확인한다.
  5. 피팅 탭 제한·닫기 — 최대 10개 제한, 활성 탭의 왼쪽 우선 닫기, 비활성 탭 닫기와 마지막 탭 보호를 확인한다.
  6. 피팅 탭 History 복원 — 이미 닫힌 과거 탭을 복원해도 현재 활성 탭의 미저장 빌드를 교체하지 않는지 확인한다.
  7. 멕 목록 정렬 — 기본·톤수·숫자 인식 알파벳순과 오름·내림차순, 진영 그룹 설정을 함께 확인한다.

기본 숫자와 장비

  1. 유효하지 않은 숫자의 기본값 — NaN이나 문자열을 안전한 기본값으로 대체한다.
  2. 탄환형 발사 수·펠릿 수 — damage × numFiring × numPerShot 직접 피해를 확인한다.
  3. 비탄환형 펠릿 중복 방지 — 미사일 등에 numPerShot을 중복 적용하지 않는다.
  4. 로켓런처 발사체 수 — 무기명의 숫자를 추론하지 않고 추출된 numPerShot만 발당 피해에 적용한다.
  5. 항상 적용되는 무기 모듈 — 호환 모듈의 additive 피해·발열을 허용 수량만큼 더한다.
  6. 스플래시와 모듈 피해 — 기본 양쪽 스플래시와 모듈 총 스플래시를 구분한다.
  7. 구조·장갑 톤수 — 구조 0.5톤 올림, 장갑 환산, 컴팩트 자이로 중량을 확인한다.
  8. 엔진 히트싱크·사이드 슬롯 — 포함 10개 제한, 추가 용량과 음수 슬롯 경계를 확인한다.

탄약·Artemis·하드포인트

  1. 활성 탄종 — Artemis 장착과 alwaysHasArtemis에 맞는 탄종을 선택한다.
  2. 발사당 탄약 소모 — ammoPerShot과 순차 발사 수를 비교하고 LB-X 펠릿 중복을 막는다.
  3. 탄약 용량 쿼크 — 정규화한 탄종과 bin 톤수로 최종 발수를 계산한다.
  4. 하드포인트 용량 — weapon_slots를 합산하고 누락 시에만 1을 쓴다.
  5. 업그레이드 슬롯 배치 — 남은 슬롯에 순서대로 배치하고 부족분을 미할당 처리한다.

내구도

  1. 내구 스킬 내림 — 장갑·구조 스킬 적용 합계를 게임 규칙대로 내림한다.
  2. 컴포넌트 최대 장갑 — 머리는 18, 나머지는 구조 HP의 두 배를 사용한다.
  3. 장갑·후면·구조 합산 — 전체·부위별 쿼크 후 스킬을 적용한다.
  4. 현재 장갑 전후면 스킬 — 실제 배분값과 쿼크를 합친 뒤 스킬 내림을 한 번 적용한다.
  5. 컴포넌트 내구 기여도 — 구조 additive와 스킬 증가분을 모두 포함한다.

기동·센서·점프젯

  1. 엔진/톤수와 기동 쿼크 — 속도, 후진, 가감속, 선회, 몸통 수치를 계산한다.
  2. 점프젯 최종 높이 — 수직 추력과 쿼크 적용 burn-time·initial-thrust를 반영한다.
  3. 센서 쿼크·장비 — 기본 센서에 쿼크 후 장비 보너스를 곱한다.
  4. 타깃 컴퓨터 필터 — 호환 무기에만 사거리·탄속·치명타 보너스를 누적한다.

무기 쿼크·연사·사거리

  1. 감소·증가·부호 보존 — 쿼크 성격에 맞는 값 방향을 사용한다.
  2. 쿨다운·듀레이션 합산 — 전체·계열·무기별 쿼크를 합산한다.
  3. 로켓런처 쿨다운 — 전체·미사일·무기별 스킬과 쿼크 감소를 적용하지 않는다.
  4. ROF 무기 — ROF 보너스로 발사 주기와 초당 피해를 갱신한다.
  5. 연속형 DAMAGE·HEAT — 머신건·RAC·빔레이저·플래머를 연속형으로 판정하고 DAMAGE와 HEAT의 /s 표시, 원본 초당 발열 HPS, 초당 DPH, 머신건 원본 발열 0을 확인한다.
  6. volley 발사 이벤트 — 이벤트 수와 이벤트 사이 시간을 계산한다.
  7. SSRM 동시 발사 — IS·Clan SSRM 2/4/6의 원본 volleydelay를 발사 시간에 더하지 않는다.
  8. 기대 쿨다운 — 충전·순차 발사·듀레이션·쿨다운을 모두 더한다.
  9. 발열·사거리 보너스 — 전체·계열·무기별 값을 올바른 방향으로 합산한다.
  10. 유해한 spread 양수 — 양수 multiplier를 제거하지 않고 산포 증가로 적용한다.
  11. 사거리 프로필 확장 — 최소사거리는 고정하고 이후 구간만 늘린다.
  12. 선형·step·지수 감쇠 — 보간 방식과 유효 범위 밖 0 피해를 확인한다.
  13. ATM 거리대 — 근·중·원거리 1.25/1/0.8 배율과 경계를 확인한다.
  14. UAC 재밍·더블탭 — 확률·지속시간 감소를 독립 적용하고 더블탭 기대 발사 수를 예상 쿨다운에 반영한다.
  15. AMS additive·ROF 총 피해율 — AMS 추가 피해와 스플래시 포함 초당 피해를 확인한다.
  16. 시뮬레이션 피해 래퍼 — 거리, 발사 수, 스플래시 옵션을 단발·초당 피해에 반영한다.
  17. 무장 상세 발사 빈도 — 0%·50%·100%의 제외와 적용 쿨타임을 확인한다.
  18. 무장·사거리 타입 토글 — 저장된 빈도를 보존하면서 해당 계산만 제외한다.
  19. 거리 눈금과 색상 — 최대 DPS 구간과 피해 0 구간의 경계·구분선을 확인한다.
  20. 무장 상세 열효율 — 75%부터 25%까지 초록색에서 빨간색으로 보간한다.
  21. ATO — 알파 사이 냉각과 고스트 힛 추가 발열을 반영한다.
  22. 툴팁 사거리 — 원본 구간의 최소·최적·최대 경계를 찾는다.

히트싱크·고스트 히트·요약

  1. 엔진·외부 히트싱크 — 첫 10개와 이후 장비의 열용량·냉각 공식을 구분한다.
  2. 고스트 히트 활성화 — HSL 전 0과 활성화 후 원래 단계부터의 누적을 확인한다.
  3. HSL 쿼크 — 전체·계열·무기별 additive를 합산한다.
  4. DPS·DPH·HPS와 열 지표 — 사이클, damage / heat, 효율과 회복시간을 계산한다.
  5. 무발열·충분한 냉각 — DPH 없음과 열효율 100% 경계를 확인한다.

빌드 집계

  1. 전체 무기 스펙 회귀 — 추출된 모든 무기를 명시적 필드와 공식으로 계산해 유효한 결과를 확인한다.
  2. 개별 공식과 최종 빌드 일치 — calculateBuild()의 톤수·화력·발열·장갑·히트싱크·슬롯 집계를 확인한다.

쿼크 이름과 +수치 공용 계산

  1. 쿼크 이름 정규화 — 앞뒤 공백과 대소문자를 제거해 같은 이름으로 비교한다.
  2. 동일 이름 수치 합산 — 대소문자가 다른 동일 쿼크의 값을 하나의 +수치로 합친다.
  3. 출처·기여도 collector — 값, Variant·옵니포드 같은 출처와 개별 기여도를 함께 보존한다.
  4. 수치 표시 문자열 — multiplier를 퍼센트로, additive를 부호 있는 값으로 변환한다.
  5. 전체·부위 additive — 전체 additive와 지정 부위 additive를 합산한다.
  6. 여러 multiplier — 지정한 multiplier 합계를 기본 배율 1에 더한다.
  7. 감소·증가·부호 보존 — 쿼크 성격에 맞는 수치 방향과 동일 이름 합산을 적용한다.
  8. 유해 duration·spread — 양수 악영향과 NARC duration 예외를 구분한다.
  9. 내구 스킬 내림 — 쿼크 적용 합계에 내구 스킬 배율을 적용하고 내림한다.

공식 변경 시 유지 규칙

  1. 변경 전에 기존 테스트와 현재 게임 데이터·구현을 확인한다.
  2. 정상값, 경계값, 0 또는 누락값 사례를 같은 작업에서 추가·수정한다.
  3. 전체 테스트, JavaScript 구문 검사, git diff --check를 실행한다.
  4. 실패가 구현 오류인지 의도된 변경인지 판별하고 근거 없이 예상값만 바꾸지 않는다.
  5. 새 계산 함수는 실제 앱 함수를 테스트 진입점에 노출하며 UI에 복제 공식을 만들지 않는다.
